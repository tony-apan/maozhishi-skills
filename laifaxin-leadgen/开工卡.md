# 开工卡（来发信）

开工先按这张卡走完，再干活。细则都在 SKILL.md 里。

1. **先核对工作流程文件**：查它在不在、对不对上（版本、范围、清单、模式、撤销办法）。在且对上，也先请用户指明这份文件、当场确认沿用，才按文件继续（每步先问即逐类先问；全自动限清单范围、首次执行前经用户点头激活一次）；还没文件、但有合规旧采纳记录的：按原记录模式办既有事项、不扩范围，引导补写文件，新增或范围不清当场问；没记录、或对不上、或与后来说法冲突的按未采纳处理——先走装后确认（顺序与话术见 references/onboarding-flow.md），模式与业务都选定后写好工作流程文件再继续。
2. **版本核对**：读官网索引里本技能包文件名所载版本，与本地 SKILL.md 的 version 字段比对；不可达改走 GitHub 公开仓同一索引。版本判定只读索引与版本清单两个数据文件。
3. **有新版再更新**：先备份旧版（将被替换的文件整份拷到同级 backup/<旧版本号>/，重名加日期后缀；不可写改拷工作区根下 backup/），再走三查：① 权限变化先报后换——逐文件比对新旧文本，涉授权、自检、更新、发送或发布权限的段落有改动，整体暂停、先报用户确认再换；② 双源核对——两处版本号一致、且本站登记摘要与公开仓同版实算摘要一致才换；只有一个来源可达时可按该源换装，报告须显名只核一源；③ 同版但内容对不上，按异常停下报告、不替换。三查都过再换装，换完重读新版。
4. **逐项汇报**：报当前版本、备份在哪、更新结果、采纳状态（只报文件在不在与模式，不读凭据）、自动运行清单、还缺什么与下一步。
5. **顺手查**：发信昵称仍是默认值的，按 §1.1 C1 给建议，确认后代改。
