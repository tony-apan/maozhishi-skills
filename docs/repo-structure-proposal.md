# LaiCMS Muse Skill 新仓结构建议
> 历史注记：本文为建仓前的结构建议稿，仓库实际结构以 docs/module-map.md 为准。

这份建议审查原库 website-content-ops 的「形」——顶层文档怎么分工、目录怎么组织、模板怎么命名——逐项给出新仓借鉴、改造还是弃用和一句理由。新仓定位与《模块地图-v1》统一：这是给中国外贸群体用的 Muse 技能全能仓，不是只装建站一个模块。本建议是全能仓的仓结构建议，建站只是 modules/website 这一个模块；其余模块（获客、B2B 平台、社媒运营、广告投放）与共用底座都在本结构里有唯一位置，不要再用「网站运营全链路仓」这类只讲建站的定位表述。本建议连同 SKILL.md 完善稿一起送独立审查，审查通过且仓名点定后再建仓，现在不建。

## 总原则：按 LLM wiki 式结构搭

- 根目录的 README 就是全仓地图，打开第一页就能看清整个仓有几层、每个文件夹干什么、想找什么去哪层，不用通读全仓。
- 每个目录都放一份 index 索引，只列本目录的文件和子目录入口，写清每份文件解决什么问题、什么时候读，目录自己解释自己。
- 索引只列本目录这一层，不把全仓文件铺平到一张大表里，顺着索引一层层往下走就能定位。
- 逻辑对人也要清晰，不只是给 AI 看：目录名和文件名优先让人一眼看懂，机器需要的编号和状态字段不进门面。
- 一份文件只干一件事，职责写在它自己的开头，两个文件说法冲突时以索引里标明的那份为准，不留第二真源。

## 逐项审查：原库有什么，新仓怎么办

1. 原库 SKILL.md 的 front matter 是状态机式重型字段（发布状态、状态投影、来源清单等十几项）。新仓弃用这套形，只借鉴 SKILL-INSTALL 里触发式的描述写法：每个模块的 SKILL.md 开头只留三样——名字、一句「什么时候用我」、版本号，把适用场景写进那一句、版本写进版本号，这样每日自更新才有东西可比对。v2 修订稿的建站 SKILL 已按此补齐开头三样。理由：小白和 Muse 都靠一句话判断要不要用这个 skill，重型状态字段没人读。
2. 原库 README 是仓库门面，讲能干什么、一键启动、三条红线和进阶入口表。新仓借鉴并升格：README 定为全仓地图，第一屏放全仓层级图和每层一句话职责，再放能干什么和红线。理由：LLM wiki 式入口靠的就是这一页，人和 AI 都先在这里定位。
3. 原库 WORKSPACE-TEMPLATE 每个目录都有一份 index.md，子库还有「目录入口文件唯一」的约定。新仓直接借鉴：每个目录放一份 index.md，只列本目录直接文件和子目录入口，并写清什么时候读。理由：目录自解释是原库最值得抄的形，找东西不用靠猜。
4. 原库 START-HERE 是一页执行入口，讲四步流程、第一条指令和停止条件。新仓借鉴：留一份「从这里开始」，只做路由和第一步，不放细则。理由：新用户和新会话都需要一个稳定不变的第一步。
5. 原库 PLAYBOOK 把全流程按阶段写在一份文件里。新仓改造：建站模块内部再按能力拆进 modules/website/playbooks，建站、美化、文章与 SEO、数据各一份；获客、B2B、社媒、广告是与 website 并列的独立模块目录，不再塞进建站的 playbooks 里当占位。每个模块的 SKILL.md 只做本模块路由。理由：全能仓定位下，单文件会越长越难维护，拆开后每条线能独立更新。
6. 原库 MENTAL-MODEL 用一页讲清底层对象和它们的关系。新仓借鉴轻量版：一页讲清站点、分类、产品、文章、页面、媒体、台账之间的关系。理由：先懂对象再动手，能少踩字段混用的坑。
7. 原库 INTAKE 的口径是先查再问、只追问阻塞项、完成时给出明确输出。新仓借鉴：改造成一份开工清单，独立成文放仓根。理由：和新 skill「先看他走到哪一步、只问最关键几件」的口径天然一致。
8. 原库 QA-CHECKLIST 把验收标准独立成文，和施工文档分开。新仓借鉴：设 checks 目录放各条线的验收清单。理由：验收标准独立，才不容易在施工时被顺手改掉。
9. 原库 WORKSPACE-TEMPLATE 是客户任务目录骨架，从 00 收件一路排到 90 交接，每层带索引。新仓借鉴改造：作为附带的 workspace-template 随仓发布，层名与 SKILL.md「资料存哪」一节同源同名，砍掉机器合同前置条件只留目录和索引。理由：用户本地真源的结构现成可用，不用另发明一套。
10. 原库 TEMPLATES 有 15 个模板加一份索引 README（共 16 个文件），规矩是按阶段只取当前需要的那份。新仓借鉴组织方式、砍合同：模板目录保留索引和英文小写连字符命名，模板正文只留人能填的字段，机器校验字段全删。理由：模板的价值在字段清单，不在机器合同。
11. 原库 SKILL-INSTALL 是独立的可安装路由层，带安装脚本和自测，skill 本体反而在别处。新仓弃用：SKILL.md 本体就是入口，不做双层。理由：双层路由会让版本口径打架，原库自己也出现过上下层结论不一致。
12. 原库有 RUNTIME-CONTRACT、SCHEMAS 和一整套机器校验脚本。新仓弃用。理由：网页路线没有程序调用这些合同，小白仓靠清单核对就够，机器合同只会吓退用户。
13. 原库 ADAPTERS 是平台适配层，按平台分目录放接口与字段合同。新仓改造：收进 modules/website/platform-laicms 目录，只放 LaiCMS 后台操作要点和坑表，不做多平台抽象；其他模块的平台要点放各自模块目录里。理由：当前建站只对接 LaiCMS 一个平台，抽象层是闲置成本。
14. 原库有按编号登记的坑库，现象、根因、修复可检索。新仓借鉴轻量版：一份坑表按现象排序、能搜到就行，不搞编号体系。理由：坑的价值在能查到，编号对单仓单人维护是负担。
15. 原库 PLAYBOOKS 用 ID 编号加英文短名给长文档命名。新仓弃用编号、借鉴一篇一主题：文件名直接用能力名，人话优先。理由：能力名本身就是最好的索引，编号对人不友好。
16. 原库有 MANIFEST、VERSION、CHANGELOG 三份状态与版本文件。新仓借鉴最小集：只留版本说明和变更记录两份。版本说明必须写清四件事：官方仓的固定地址（可信来源只认这一个）、当前正式发布的版本号与发布标签、对应的提交编号、退回上一版的办法；变更记录要标出哪些改动涉及凭据、对外发送、删除、发布、渠道读取，这几类改动不能沿用旧授权自动生效，须用户点头。理由：skill 每天自查更新要靠版本号比对和可回退，状态机三件套过重。
17. 原库 EXAMPLES 放示例和演练材料。新仓借鉴：放一份脱敏的样例交付包结构，让人看到一份完整交付长什么样。理由：小白看样例比看规则快得多。
18. 原库 SOURCES 和 WRITEBACK 把来源登记与写回规则独立成文。新仓改造：来源登记并入工作区模板的来源层，写回规则并入各 playbook 的收尾一节，不在 skill 仓单列。理由：这两件是用户工作区里的日常动作，不是仓的门面。
19. 原库有 BRAND、CONTACT、LICENSE 等治理文件。新仓借鉴最小集：只留许可和一份联系说明，联系说明里写清没有 LaiCMS 账号时联系官方开通的真实入口；建站 SKILL 在用户没账号时直接引用这份联系说明发给用户，不自己编造渠道。理由：公开仓需要许可与联系入口，其余治理文件有需要再加。
20. 原库 TOOLS 和 scripts 目录放着大量工具脚本。新仓弃用进仓：脚本只留维护者本地，不随 skill 发布。理由：网页路线不依赖本地脚本，脚本进仓只会让小白用户困惑。

21. 原库 REFERENCES 里有官方教程索引（带核对日期）和官方来源登记。新仓借鉴并落到执行层：在仓根设 references 目录放 allincms-官方教程索引.md，每条记标题、官网地址、要点三行、抓取日期；建站 SKILL 执行时先读索引、再打开官网最新版核对，官网与索引不一致以官网为准并更新索引。理由：教程保鲜不能只写在模块地图里，必须在 SKILL 和仓结构里都有落点。
22. 模块地图定的多模块结构。新仓按 common 加 modules 落地：共用底座（账号三路引导、密码库、资料真源、自更新与教程保鲜、Muse 邮箱）只放 common 一处，各模块只引用、不各写一份；社媒发布只归 modules/social 执行，建站模块只备帖、交文章链接和摘要，避免同一篇文章两个模块各发一遍；未启 social 时建站按其 SKILL 写明的受控代理发布例外经授权代发，与 social 共用同一份发布记录，并按「待移交／已移交待发布／发布中／已发布／结果不确定」状态机防重复——已移交待发布允许指定 social 执行者接续首发，只禁止重复移交和建站代发；只有已发布禁止再发；结果不确定先核验。启用 social 后新任务例外停用，在途任务按原指定执行者处理完或显名改派。理由：底座多处复制必然口径打架，发布双归属必然重复发。

## 命名约定（全仓只这一条）

- 面向人读的目录和文件用中文人话名（如 建站.md、联系说明.md）；模板目录和需要被程序或路径引用的目录用英文小写连字符（如 templates、platform-laicms、references）；同一个目录里不混用两套命名，拿不准时以人能一眼看懂为准并在该目录索引里写清。

## 新仓目录草案

仓根结构如下，每一层目录里都放一份 index.md 说明本层内容与入口，仓根用 README 当全仓地图、不再另设根索引：

- 根目录：README.md（全仓地图）、版本说明.md、变更记录.md、LICENSE、联系说明.md。根 SKILL 只做全仓路由，不放任何模块的施工细则。
- common 目录（共用底座，只此一份）：账号引导（授权页登录、扫码登录、密码库三路分开写）、密码库说明、绑定体系、Muse 邮箱、资料真源与本地工作区规范、自更新与回退规则、教程保鲜规则。各模块需要底座能力时只引用这里，不复制正文。
- modules/website 目录（独立站模块）：SKILL.md（开头三样加本模块路由）、playbooks（建站、美化、文章与 SEO、数据与日报四份）、templates（产品事实底稿、文章选题单、客户原话提炼卡、图片清单、发布记录、故障记录六份，与 SKILL 附录的六种格式同源）、platform-laicms（后台操作要点、坑表两份）、checks（全站验收清单）。
- modules/leadgen 目录（获客模块，来发信）：先占位登记，方案定版后按同一形制补 SKILL 与 playbooks。
- modules/b2b 目录（B2B 平台模块）：先占位登记，免费 B2B 注册、阿里巴巴国际站上传、中国制造网上传后续逐个补。
- modules/social 目录（社媒运营模块）：社媒发布的唯一执行归属在这里；建站模块只把新文章的链接和摘要交过来，不自己发；未启本模块时建站的受控代理发布例外与全仓共用发布记录口径，见建站 SKILL 的社媒分发小节。共用记录按五种状态流转，已移交待发布允许指定 social 执行者接续首发、只禁止重复移交和建站代发，只有已发布禁止再发，结果不确定先核验，全仓只用这一套。
- modules/ads 目录（广告投放模块）：预留占位。
- references 目录：allincms-官方教程索引.md 一份起步，后续各平台官方教程索引按平台分文件加进来，每条带抓取日期。
- workspace-template 目录：用户本地工作区骨架，00 收件、10 来源登记、20 知识底稿、30 任务清单、40 产出、50 数据、90 交接七层，每层一份 index.md，与建站 SKILL「资料存哪」一节同源同名（90 层全仓统一叫「交接」）。
- examples 目录：脱敏样例交付包一份。

## 暂不进仓的东西

- 用户的真实资料、站点数据和运行记录永远不进这个仓，它们只住在用户本地工作区，仓里只放方法和模板。
- 旧工具包的 API 通道、载荷与脚本不进仓，网页路线用不上，进仓只会误导。
- 发布状态、审查状态这类过程性记录不进仓，留在票面和台账里，仓只保留对外稳定的版本。
