# 全能仓模块地图 v1（Tony 2026-11-12 口头定调）

定位：给中国外贸群体（工厂、贸易商、工贸一体、外贸服务商、SOHO）用的 AI 工作技能全能仓。一个仓、多个模块、共用一套底座。资料只录一次，多个模块复用。

## 共用底座（所有模块共用，不重复造）

- 账号引导分三路，不要混成一套：授权页登录（OAuth，适用于 GitHub、Gmail、Outlook、Google、Notion、Facebook 等，用户本人在授权页确认，不收密码）、扫码登录（WhatsApp 网页版，用户手机扫码）、密码库（只有账号密码的后台如 LaiCMS，才走安全录入卡四步存 Muse 设置里的密码库，聊天不收明文）。每一路开始前先核验能力可用与授权范围，不可用时给用户接管或替代路线
- 绑定体系：Gmail 与 Outlook、WhatsApp 网页版扫码、Google 账号、GitHub、Notion、Facebook、Instagram 和 Messenger，按模块需要引导绑定
- Muse 邮箱：开工先查有没有设置，没设置引导创建（按昵称与公司名给地址建议），绑常用邮箱（优先绑微信的 QQ 邮箱）收询盘提醒与日报
- 资料真源：用户本地工作区文件夹，Markdown 为主、每层带索引；一份产品事实底稿喂全部模块；Google 表格只做数据展示层
- 用户资料库（共用底座，各模块开工先读）：按四格建——① 公司档案（公司英文名、品牌、联系方式、主营与优势，只记用户确认过的事实）② 产品事实底稿（一产品一档：名称、规格、用途、卖点、图片与视频素材路径，全部模块写信/上架/发帖只从这里取数，不许临场编）③ 素材库（产品图、场景图、文案片段、证书文件，各带一行说明与来源）④ 数据与台账（找客台账、发送记录、询盘记录，按各模块口径落表）。存放：用户本地工作区为真源，整体同步进用户本人专属私有仓或云盘（换设备/换账号靠它衔接）；每格一个索引文件，新资料先入格再被引用，找不到就显名缺、不许猜
- 自更新与保鲜：每天先查仓更新再干活，只认版本说明里锁定的官方仓地址与带标签的正式发布，记提交编号，涉及凭据、外发、删除、发布、渠道读取的规则变更须用户点头，换版留旧版可回退；官方教程真源在官网，仓里在 references 目录只存索引与要点加抓取日期，执行时先读索引、再打开官网最新版核对，不一致以官网为准并更新索引

## 目录对齐（与仓结构建议同一套）

注：本节为目标形态；当前仓实际结构为根目录平铺（`laicms-site-builder/`、`laifaxin-leadgen/`、`workspace-template/`、`docs/`），向目标形态的拆分迁移列为公开发布前施工项，未执行前以实际结构为准。

- common/ 放共用底座，只此一份，各模块只引用。
- modules/website、modules/leadgen、modules/b2b、modules/social、modules/ads 与上面五个模块一一对应，每模块一个子目录加一份 SKILL。
- references/ 放各平台官方教程索引；workspace-template/ 放用户本地工作区骨架；仓根 README 是全仓地图，每层有索引。

## 梳理原则

- 模块按用户干活的场景切，不按工具切
- 每个模块一个子目录加一份 SKILL，根目录 README 是全仓地图，每层有索引
- 新模块先占位登记在本图，再立项施工，不许写进已发布模块的正文充数
