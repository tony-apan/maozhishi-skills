要不要开多语言

结论先行

Section titled “结论先行”

你问多语言、翻译整站、要做小语种市场时，我们的建议是：不建议在主站开启平台的多语言功能；先把英语站做完整、跑出效果；之后要打某个地区或小语种市场，单独为它建一个当地语言的独立站。 多个独立站组成站群，效果比一个站开多语言更好。

推荐路线

Section titled “推荐路线”
  1. 先英语：主站默认语言用英语（目标市场以英语国家为主时），产品、文章、页面、菜单、联系信息全部做完整，先跑出收录和询盘。
  2. 见效后逐个扩站：哪个地区有反馈、有市场，就为它新建一个独立站——当地语言、当地客户搜的词、当地市场在意的内容，逐站单独优化、单独验收。
  3. 站群运营：每个站都是完整独立站，各自绑域名、各自维护更新；新站可以复用主站的产品资料，但文案按当地市场重写，不整站搬运机翻。

为什么站群更好

Section titled “为什么站群更好”
  • 平台多语言是把一份内容整站机翻成多个语言版本：参数、品牌名、本地说法容易失真，翻完还要逐语言人工核对，原文每改一次、各语言版本都要跟着重检。
  • 独立站每种语言都是一份为当地市场单独做的内容：客户搜什么词、关心什么参数、习惯什么说法，都能针对性地写，更容易把当地市场的收录和信任做扎实。
  • 主站只用一种语言，语言信号干净，不被多语言版本互相稀释。
  • 一个市场一个站，哪个站要调整、暂停、换方向，都不牵连其他站。

注意

这是建议，不是拦截：理由讲清之后，你仍要开多语言的，AI 会照下面的官方流程完整引导你开，不拒绝、不拖延。坚持开、但前置条件不满足时，先帮你补齐前置再开——那是流程顺序，不是把建议变回门槛。

坚持开多语言时：官方流程

Section titled “坚持开多语言时：官方流程”
  1. 前置两件：默认语言的内容基本完整（产品、文章、页面、菜单、联系信息都已确认）；AI API 已绑定并测试连接成功——没绑 API，系统无法翻译（绑法看 《给网站接 AI》）。
  2. 添加语言：后台「设置 → 站点语言」→「添加语言」，只勾真实目标市场的语言，不为好看全开。默认语言非必要不换：更换会改变已收录页面的语言信号，影响搜索收录的持续判断。
  3. 等翻译完成：添加后系统在后台整站翻译，前台照常访问。回「站点语言」看每种语言的已翻译／未翻译／翻译失败三个数，后两个不为 0 就还没翻完，不要把翻译中的版本当最终结果推广。
  4. 补翻：多种语言都不全，点「全站翻译」；只有一种不全，点该语言行末菜单里的「重新翻译」。任务进行中不要反复点击。
  5. 前台验收：前台有语言切换入口（官方文档标注在右上角，实际位置以当前主题为准），逐个语言切过去查菜单、页面、产品、文章。注意：网站会按访客的浏览器语言自动匹配已启用语言，没启用就回退默认语言——自己用中文浏览器打开显示中文，不是翻译失败。最后逐语言人工确认产品参数、品牌名、联系方式，AI 翻译只是初稿。
