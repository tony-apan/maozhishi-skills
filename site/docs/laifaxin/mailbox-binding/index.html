邮箱绑定指南

想用自己的邮箱给重点客户一对一发信（精发），先把邮箱绑到来发信。Gmail / Outlook 走授权页面点确认就行；其他邮箱走这一篇：用「授权码」绑定。

警告

先记住一条：授权码由你本人在邮箱后台生成、自己粘贴进来发信的绑定框，不要发给任何人，也不要发到聊天里让 AI 代填。 绑不上的时候让 AI 带你一步步排查，凭据始终只进平台。

1. 先分清密码类型（绑不上多半是用错密码）

Section titled “1. 先分清密码类型（绑不上多半是用错密码）”
密码类型 是什么 哪些邮箱用
授权码 / 应用专用密码 / 应用密码 / 客户端安全密码 / 独立密码 邮箱给第三方客户端的独立密码，各家叫法不同、本质同一种东西；可单独撤销，不影响主账号 绝大多数（Gmail、QQ、163、Outlook、企业邮箱全系）
登录密码 你登邮箱网页用的密码 少数（阿里邮箱、电信 189/21cn）

判断法：先看是不是 Outlook/Hotmail——是则优先走授权页面那条路（OAuth）：它的应用密码需先开两步验证，且部分账号已不提供应用密码入口，这类账号不要硬绑授权码这条路，能生成应用密码的才走。其余邮箱：开了两步验证 → 绝大多数要用应用专用密码/授权码；不确定就优先生成应用专用密码（比直接用登录密码稳妥：可单独撤销、不暴露主密码；只能用登录密码的几家按上表执行）。

个人邮箱速查（16 家）：Gmail 应用专用密码｜Outlook/Hotmail 应用密码｜Yahoo 应用程式密码｜iCloud 专用密码｜AOL app 密码｜Yandex 应用密码｜mail.ru 应用程序密码｜QQ/Foxmail 授权码｜网易（163/126/yeah/188）授权码｜新浪 授权码｜搜狐 独立密码｜阿里邮箱 登录密码｜移动 139 客户端密码｜电信 189 登录密码｜电信 21cn 登录密码｜完美（88.com 等）专用密码。

企业邮箱速查（7 家，无一可用登录密码）：Google Workspace 应用专用密码｜263 客户端授权码｜阿里云 客户端安全密码｜网易企业 授权码｜腾讯企业 授权密码｜35 授权码｜Zoho 应用专用密码。

不支持 POP3：来发信只走 IMAP（收）＋SMTP（发）。

2. 服务器参数表（已核对 5 家）

Section titled “2. 服务器参数表（已核对 5 家）”
邮箱 IMAP（收） SMTP（发）
Gmail imap.gmail.com:993 SSL smtp.gmail.com:465 SSL 或 587 TLS
QQ imap.qq.com:993 SSL smtp.qq.com:465 SSL
网易 163 系 imap.163.com:993 SSL smtp.163.com:465 SSL
Outlook/Hotmail outlook.office365.com:993 SSL smtp.office365.com:587 TLS
腾讯企业邮箱 imap.exmail.qq.com:993 SSL smtp.exmail.qq.com:465 SSL

其余各家的参数在来发信官网对应单篇里（个人速查与企业速查两页有全表入口），绑定时照单篇填，不要凭记忆填。

3. 跟着检查点走（一步一步来）

Section titled “3. 跟着检查点走（一步一步来）”

让 AI 带你走也行，自己照着走也行，一次只走一个检查点：

  • 检查点 0（企业邮箱先行）：先确认你有没有邮箱管理后台权限。企业邮箱的 IMAP/SMTP 服务常默认关闭、要管理员开；没有权限先去找管理员，别在设置页空翻。
  • 检查点 1（开服务）：按该邮箱官网单篇的路径打开 IMAP/SMTP 服务（Gmail 要先在 Google 账号里开两步验证，才有应用密码入口）。卡点：找不到入口，多半是服务没开或没开两步验证。
  • 检查点 2（生成并保存）：生成授权码/应用专用密码。注意：只显示一次，生成后立刻存进密码管理器（如 1Password、Bitwarden），丢了只能作废重生成；每个客户端单独生成一个（来发信专用一个），便于单独撤销。
  • 检查点 3（回平台绑定）：你自己把授权码粘贴进来发信绑定框，填第 2 节的参数，填完要点保存/绑定按钮才生效——只填不点等于没绑。
  • 检查点 4（双验）：验证通过后开邮件同步（间隔设 3–5 分钟，短于 3 分钟可能触发限流），发一封测试信确认发得出、同步确认收得到，双验过才算绑好。测试信可以让 AI 在来发信界面帮你发，发之前它会把发信身份、收件地址、内容逐项念给你确认。

提示

需要发截图给 AI 排查时，先把授权码、验证码、手机号遮住再发；万一截图里出现了完整授权码，把那个码作废、重新生成一个。

高频卡点：入口不显示＝没开两步验证（Gmail）；535＝密码类型用错；短信验证失败＝要用绑定手机号、内容完全按提示（含大小写）。

4. 绑失败错误码自查表

Section titled “4. 绑失败错误码自查表”
报错 含义 处理
535 Authentication failed 密码错，或没用应用专用密码 用授权码/应用专用密码重绑（最常见）
534 5.7.9 Application-specific password required 开了两步验证却用普通密码 去生成应用专用密码
Connection refused 服务器地址/端口填错 按第 2 节参数表或官网单篇核对
Connection timeout 防火墙/VPN 拦截 465/587 端口 关 VPN 或换网络
SSL handshake failed 加密方式选错 993 用 SSL、587 用 TLS
Login disabled / IMAP disabled 后台没开 IMAP/SMTP 服务 先到邮箱后台开启（企业邮箱可能要管理员）
Too many connections 同步太频繁被限流 同步间隔调到 5–10 分钟
DNS 解析失败 服务器地址拼写错 核对地址拼写
反复弹密码框 授权过期 重新生成授权码，回平台更新

5. 绑好之后的维护

Section titled “5. 绑好之后的维护”
  • 邮箱改了登录密码或授权码被作废 → 立即回平台更新凭据并保存，否则全部发信失败。
  • 每季度看一眼邮箱后台的已授权设备/授权码列表，关掉不用的。
  • 邮箱异常（被标红箱、连续退信）先停用该箱排查，不硬发。

6. 友情提醒（提醒到位，坚持就照发）

Section titled “6. 友情提醒（提醒到位，坚持就照发）”

友情提醒：常用邮箱和办公邮箱大批量发信很容易被封号，企业邮箱还会连累全公司域名信誉、全公司同事的邮件都可能进垃圾箱；量大建议走平台的优质通道。你了解风险后仍要用自有邮箱发，照常发，量和节奏按保守口径走。

绑邮箱时和首次批量发送前，AI 都会提醒你一次。提醒是提醒，不是门槛：你确认后照常执行。
