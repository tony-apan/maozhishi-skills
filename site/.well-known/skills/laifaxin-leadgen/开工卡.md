# 开工卡（来发信）

开工先按这张卡走完，再干活。细则都在 SKILL.md 里。

1. **先核对工作流程文件**：查它在不在、对不对上（版本、范围、清单、模式、撤销办法）。在且对上，也先请用户指明这份文件、当场确认沿用，才按文件继续（每步先问即逐类先问；全自动限清单范围、首次执行前经用户点头激活一次）；还没文件、但有合规旧采纳记录的：按原记录模式办既有事项、不扩范围，引导补写文件，新增或范围不清当场问；没记录、或对不上、或与后来说法冲突的按未采纳处理——先走装后确认：讲清读什么、改什么、是否外发、是否后台运行，请用户当场确认采纳并选模式（1 全自动／2 每步先问），确认后写好文件再继续。
2. **版本核对**：读展示站 skill.maozhishi.com 根目录的 VERSION 与 release-manifest.json，与本地仓根 VERSION 比对；不可达改走 GitHub 公开仓。版本判定只读这两个数据文件。
3. **有新版再更新**：先备份旧版（拷到仓根 backup/<旧版本号>/ 下，重名加日期后缀；没工作区也要备），再走三查：① 权限变化先报后换——逐文件比对新旧文本，涉授权、自检、更新、发送或发布权限的段落有改动，整体暂停、先报用户确认再换；② 双源核对——两处版本号一致、且本站登记摘要与公开仓同版实算摘要一致才换；只有一个来源可达时可按该源换装，报告须显名只核一源；③ 同版但内容对不上，按异常停下报告、不替换。三查都过再换装，换完重读新版。
4. **逐项汇报**：报当前版本、备份在哪、更新结果、采纳状态（只报文件在不在与模式，不读凭据）、自动运行清单、还缺什么与下一步。
5. **顺手查**：发信昵称仍是默认值的，按 §1.1 C1 给建议，确认后代改。
