# 开工卡（来发信）

开工先按这张卡走完，再干活。

1. **先核对工作流程文件**：查在不在、对不对（版本、范围、清单、模式、撤销办法）。在且对上，请用户指明文件、当场确认沿用再继续（每步先问即逐类先问；全自动限清单，首次经用户点头激活一次）；没文件但有合规旧采纳记录的：按原记录模式办既有事项、不扩范围，引导补写，新增或范围不清当场问；没记录、对不上或与后来说法冲突的按未采纳处理——先走装后确认（见 references/onboarding-flow.md），选定后写好再继续。
2. **版本核对**：官网索引里包文件名所载版本（不可达改走 GitHub 公开仓索引），与本地 SKILL.md 文件头 version 字段比对；判定只读索引与版本清单。
3. **有新版再更新**：先备份旧版（拷同级 backup/<旧版本号>/，重名加日期后缀；不可写改拷工作区 backup/），再走三查：① 权限变化先报后换——逐文件比对新旧文本，涉授权、自检、更新、发送或发布权限的段落有改动，整体暂停、先报用户确认再换；② 双源核对——两处版本一致、且本站登记摘要与公开仓同版实算摘要一致才换；只一源可达可按该源换装，报告显名只核一源；③ 同版内容对不上，按异常停报、不替换。三查过再换装，换完重读新版。
4. **逐项汇报**：报当前版本、备份在哪、更新结果（含回滚标记）、采纳状态（只报在不在与模式，不读凭据）、自动运行清单、缺什么与下一步。
5. **顺手查**：发信昵称仍是默认值的，按 §1.1 C1 给建议，确认后代改。
6. **版本三方对账（§1.7）**：版本记录（实装／最高已装／回滚标记）、文件头登记、官网当前版对一遍，不符只报；落后官网每次开工提示（已列自动更新除外）。
