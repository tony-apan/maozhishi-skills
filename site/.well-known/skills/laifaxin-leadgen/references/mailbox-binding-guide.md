# 来发信邮箱绑定指南（参数速查与授权码引导）

> 用途：精发路线乙「平台绑箱」的操作附录。SKILL.md §1.1 第 2 步与 §4.2 引用本文。
> 数据来源：来发信官网教程《邮箱账号》总篇、个人邮箱速查、企业邮箱速查、Gmail 与网易单篇（2026-11-16 抽验）；其余各家单篇与官网同模板，未逐篇复验，细节以官网单篇为准；飞书/Lark 参数经飞书与 Lark 官方帮助核对（2026-11-20），免费企业邮箱开通流程借鉴来发信官方教程《免费企业邮箱之001-larksuite（飞书海外版）》。
> 红线：授权码/应用专用密码由用户本人在邮箱后台生成、自己粘贴进来发信平台绑定框，**不经 Muse、不进聊天**（路线丙 §7 不走本条路径：不经平台绑定框，凭据由用户经 Claude Codex 安全录入、只进保险库，是本条的唯一例外）。本红线只针对**邮箱凭据**；来发信平台账号本身的登录走保险库、是 SKILL 既有口径，两者不要混。

## 1. 先分清密码类型（绑不上多半是用错密码）

| 密码类型 | 是什么 | 哪些邮箱用 |
| --- | --- | --- |
| 授权码 / 应用专用密码 / 应用密码 / 客户端安全密码 / 独立密码 / 专用密码 | 邮箱给第三方客户端的**独立密码**，各家叫法不同、本质同一种东西；可单独撤销，不影响主账号 | 绝大多数（Gmail、QQ、163、Outlook、企业邮箱全系） |
| 登录密码 | 你登邮箱网页用的密码 | 少数（阿里邮箱、电信 189/21cn） |

判断法：**先看是不是 Outlook/Hotmail**——是则优先走路线甲（OAuth）：它的应用密码需先开两步验证，且部分账号已不提供应用密码入口，这类账号不要硬绑路线乙，能生成应用密码的才走路线乙。其余邮箱：**开了两步验证** → 绝大多数要用应用专用密码/授权码；不确定就优先生成应用专用密码（比直接用登录密码稳妥：可单独撤销、不暴露主密码；只能用登录密码的几家按上表执行）。

**个人邮箱速查（16 家）**：Gmail 应用专用密码｜Outlook/Hotmail 应用密码｜Yahoo 应用程式密码｜iCloud 专用密码｜AOL app 密码｜Yandex 应用密码｜mail.ru 应用程序密码｜QQ/Foxmail 授权码｜网易（163/126/yeah/188）授权码｜新浪 授权码｜搜狐 独立密码｜阿里邮箱 登录密码｜移动 139 客户端密码｜电信 189 登录密码｜电信 21cn 登录密码｜完美（88.com 等）专用密码。

**企业邮箱速查（9 家，无一可用登录密码）**：Google Workspace 应用专用密码｜263 客户端授权码｜阿里云 客户端安全密码｜网易企业 授权码｜腾讯企业 授权密码｜35 授权码｜Zoho 应用专用密码｜飞书（国内版） 专用密码｜Lark（飞书海外版） 专用密码。

**不支持 POP3**：来发信只走 IMAP（收）＋SMTP（发）。

## 3. 授权码获取：检查点引导（陪用户一步步走）

引导分工：**看步骤、报检查点由 Muse 做；扫码登录、短信验证、输登录密码等身份动作一律用户本人在自己的浏览器里做**，Muse 不代登、不接管。一次只给一个检查点，用户回「好了」再给下一个。

- **检查点 0（企业邮箱先行）**：先问用户有没有邮箱管理后台权限。企业邮箱的 IMAP/SMTP 服务常默认关闭、要管理员开；没有权限先去找管理员，别在设置页空翻。
- **检查点 1（开服务）**：按该邮箱单篇路径打开 IMAP/SMTP 服务（如网易：网页版；QQ 同名页；Gmail 在 Google 账号里开两步验证后才有应用密码入口）。卡点：找不到入口多半是服务没开或没开两步验证。
- **检查点 2（生成并保存）**：生成授权码/应用专用密码。**先提醒：只显示一次，生成后立刻存进密码管理器**（如 1Password、Bitwarden），丢了只能作废重生成；每个客户端单独生成一个（如来发信专用一个），便于单独撤销。
- **检查点 3（回平台绑定）**：用户自己把授权码粘贴进来发信绑定框，填 §2 参数，**点**才生效——只填不点等于没绑。
- **检查点 4（验收）**：平台【验证并保存】通过后开邮件同步（间隔设 3–5 分钟，短于 3 分钟可能触发限流（平台教程口径）），验证通过＋开同步，两样都齐才算绑好（去测试化定版：不再发测试信验收）；首封真实发送发不出时，由 AI 按本文 §4 错误码表先行排查，解决不了再报用户。执行主体：测试信由执行本 Skill 的 AI 在来发信界面操作发出（平台登录走保险库），发前把发信身份、收件地址、内容逐项念给用户确认；用户负责的是邮箱一侧的身份动作与授权码粘贴；测试信发送失败时由 AI 按本文 §4 错误码表先行排查，解决不了再报用户。
- **截图纪律**：需要用户发截图排查时，先提醒遮住授权码、验证码与手机号再发；万一截图里出现完整授权码，不要复述它，并提醒用户该码作废重生成。

高频卡点：入口不显示＝没开两步验证（Gmail）；535＝密码类型用错；短信验证失败＝须用绑定手机号、内容完全按提示（含大小写）。

### 飞书 / Lark 的具体走法（§3 检查点在这一家的形态）

- **先行条件（检查点 0 的飞书形态）**：管理员先在管理后台开启「第三方邮箱客户端」权限（Lark：管理后台 → 产品设置 → 邮箱 → 邮箱管理工具 → 用户功能权限 → 第三方邮箱客户端 → 开启；飞书国内版在管理后台邮箱设置里开同名权限）。不开，成员在自己设置里看不到生成入口——先找管理员，别在设置页空翻。
- **生成专用密码（检查点 1–2 的飞书形态）**：只能在桌面客户端（飞书/Lark 电脑端）做：头像 → 设置 → 邮箱 → 第三方邮箱客户端登录 → 立即设置 → 选设备 → 生成；网页端、手机端都生成不了。生成页同时显示服务器参数与专用密码，按检查点 2 的纪律当场存进密码管理器。
- **公共邮箱**（info@、sales@ 这类）：由管理员在管理后台（产品设置 → 邮箱 → 地址管理 → 公共邮箱 → 编辑）开启 IMAP/SMTP 并重置该公共邮箱的 IMAP/SMTP 密码，拿这个密码按路线乙绑；成员个人邮箱走上面两步生成自己的专用密码。
- **绑定动作**：回来发信【新建】邮箱账户，填邮箱地址＋专用密码；平台自动识别服务器就直接验证，识别不了按 §2 参数手填；点【验证并保存】后照常走检查点 4 双验。
- **还没有企业邮箱的用户（开户路）**：自备域名可开 Lark 免费企业邮箱（飞书海外版）——免费版当前权益（来发信官方教程口径，以 Lark 官网为准）：100G 容量、每天发信上限 450 封、20 个公共邮箱；注册与域名设置全程需全局网络代理；图文全流程见来发信官方教程《免费企业邮箱之001-larksuite（飞书海外版）》（doc.laifa.xin/share/mailbox/free-enterprise-email-larksuite.html）。开好后就是公司域名企业邮箱（选箱顺序首选档），再按本节绑回来发信。450 封/天是 Lark 的平台上限、不是建议发送量，绑箱发送照常按本 Skill 保守口径执行。

## 4. 绑失败错误码自查表

| 报错 | 含义 | 处理 |
| --- | --- | --- |
| 535 Authentication failed | 密码错，或没用应用专用密码 | 用授权码/应用专用密码重绑（最常见） |
| 534 5.7.9 Application-specific password required | 开了两步验证却用普通密码 | 去生成应用专用密码 |
| Connection refused | 服务器地址/端口填错 | 按 §2 参数表或官网单篇核对 |
| Connection timeout | 防火墙/VPN 拦截 465/587 端口 | 关 VPN 或换网络 |
| SSL handshake failed | 加密方式选错 | 993 用 SSL、587 用 TLS |
| Login disabled / IMAP disabled | 后台没开 IMAP/SMTP 服务 | 先到邮箱后台开启（企业邮箱可能要管理员） |
| Too many connections | 同步太频繁被限流 | 同步间隔调到 5–10 分钟 |
| DNS 解析失败 | 服务器地址拼写错 | 核对地址拼写 |
| 反复弹密码框 | 授权过期 | 重新生成授权码，回平台改密码并 |

## 5. 绑好之后的维护

- 邮箱改了登录密码或授权码被作废 → 立即回平台更新凭据并点，否则全部发信失败。
- 每季度看一眼邮箱后台的已授权设备/授权码列表，关掉不用的。
- 邮箱异常（被标红箱、连续退信）先停用该箱排查，不硬发。

## 6. 友情提醒（提醒到位，用户坚持就照发）

绑箱时与首次批量发送前各提醒一次：

> 友情提醒：常用邮箱和办公邮箱大批量发信很容易被封号，企业邮箱还会连累全公司域名信誉、全公司同事的邮件都可能进垃圾箱；量大建议走优质通道。你了解风险后仍要用自有邮箱发，照常发，量和节奏按保守口径走。

提醒是提醒，不是门槛：用户确认后照常执行，不许以提醒为由拒绝或拖延。

## 7. 路线丙：直接绑进 Claude Codex（通用 IMAP/SMTP）

- **定位**：邮箱不经来发信平台，由用户自己的 Claude Codex 用 IMAP（收）＋SMTP（发）直连邮箱。任何支持 IMAP/SMTP＋授权码/专用密码的邮箱都适用（飞书/Lark、QQ、163、各类企业邮箱）；Gmail/Outlook 已有路线甲（OAuth）时优先路线甲，本路线补的是没有 Claude Codex 连接器的邮箱。本路线以用户所在环境具备安全录入与保险库（凭据安全存储）为前提，不具备的环境不启用本路线、按路线乙走平台绑箱。
- **用途边界**：主要用于询盘成立后的跟进与用户自己的邮件处理；冷开发仍走系统通道，两段式分工不变；发送量照常按自有邮箱保守口径（新箱爬坡与单箱日限）执行。
- **凭据纪律（本路线口径，本文头部红线的唯一例外）**：授权码/专用密码由用户本人经 Claude Codex 的安全录入存进保险库，运行时从保险库取用；不进聊天、不进台账、不进备份、不写进任何 skill 文件与工作区文件。本文只记服务器参数与流程，永不记任何人的凭据。
- **启用检查点**：① 按 §1 分清密码类型、按 §3 检查点在邮箱侧开好 IMAP/SMTP 并生成专用授权码（飞书/Lark 先走 §3 的飞书/Lark 具体走法：管理员开权限、桌面端生成）；② 用户经安全录入把授权码存进保险库（所在环境不支持安全录入/保险库的，到此为止、不启用本路线）；③ 按 §2 参数做连通验收——IMAP 能拉到收件箱、SMTP 以首封真实发送并回读为准；④ 验收结果记台账（只记邮箱地址、参数、日期、结论，不记凭据）。
- **状态（诚实口径）**：本路线为已立设计、未端到端实测。首次给某个用户启用时按上面检查点逐项验，验过之前不许对用户说「已经通了」；实测过的邮箱类型逐个登记在本节末尾（当前：无）。
