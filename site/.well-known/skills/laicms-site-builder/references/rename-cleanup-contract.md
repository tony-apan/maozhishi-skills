# 改名清理解析契约

> 用途：两个技能 SKILL.md 的「改名清理」条指向本文。只在版本清单真有改名登记时才需要读，日常不读。

改名清理：新版在版本清单 `release-manifest.json` 里登记了改名映射（`renames`）时，更新后按映射逐项处理旧名文件。映射的读取范围写死：本地版本之后、目标版本为止的全部条目（跨多版升级逐条都读），多条目时按版本从旧到新逐个条目处理，不合并成一张总表——仅当旧名文件的内容与上一发布版原文逐字节一致时才删除；内容不一致的旧名文件一律保留，并在更新报告里列明请用户决定。上一发布版＝本次更新开始前本地 `VERSION` 里的版本号，须在更新覆盖 `VERSION` 前记录；其原文指该版本官方发布包（GitHub 官方仓对应版本的 Release 压缩包；本站只留当前版，旧版以公开仓为准）里同路径文件的内容。取不到原文属正常分支（不算异常），按“已被改动”处理、保留不删。workspace-template 里已填写的内容与用户数据区永不按映射清理：`renames` 的 `from` 落在这两处范围内的，该项不处理，并在报告里列明。

解析契约：先适用“更新检查只读数据文件”条的清单异常规则；凡该条规定按无登记处理的情形，均不执行任何改名清理，并按该条报告。清单无上述异常时，按上述范围逐个条目读取 `renames`：范围内条目都没有 `renames`、或全部为空数组，视为无改名登记、不做清理，不算失败；目标版本条目缺失按清单异常处理；本地版本早于清单最早条目时，读取范围以清单内全部条目为限（清单设立之前的版本从未登记过改名映射，完整历史见 HISTORY.md）。执行分三段写死：先读齐范围内全部条目并逐条目完成整组校验，任一条目校验不过则整个改名清理失败关闭、不动任何文件；全部条目校验通过后，才按条目从旧到新依次做逐项状态判定；判定齐了最后统一删除。

`renames` 必须为数组，每项必须为 JSON 对象，并含有字符串类型的 `from`、`to` 两个字段；其他字段不参与改名清理。`from`、`to` 均为仓库相对路径。路径语法写死：只许 `/` 分隔，须非空，不许含反斜杠，不许以盘符（如 `C:`）或 `/` 开头，不许含 `..` 段、`.` 段或空段；同一项的 `from` 与 `to` 不许相同。路径匹配与冲突判断均按完整路径字符串精确比对、区分大小写，不做去空白、大小写折叠或路径规范化；仓内路径均为 ASCII 文件名，不另设 Unicode 规范化。

映射冲突的定义（只在单个条目的数组内判定，跨条目不算冲突）：同一 `from` 出现多次、两个不同 `from` 指向同一 `to`、或任一 `from` 同时出现在同一条目的 `to` 集合里（链式映射），都算冲突。以下格式、路径与冲突校验以单个条目的 `renames` 数组为单位；每个条目都必须整组校验通过，并按「解析契约」段的三段顺序执行（全部条目先校验、再判定、后删除）；`renames` 不是数组、任一条目格式不符、任一路径不合法或存在任一映射冲突时，整个改名清理失败关闭，不得先过滤无效项再处理其余项。失败关闭只针对改名清理本身：更新照常完成，不执行任何改名清理，并在报告里说明原因。

逐项状态处置以更新完成后、执行任何改名删除前的文件状态为准，按条目从旧到新的顺序依次判定；同一路径已在先前条目里被判为待删除的，后续条目里再出现时跳过该项并在报告里注明。单个条目内的逐项判定按以下顺序：

1. `from` 落在上述禁止清理范围内：不处理，并在报告里列明。
2. `from` 本身或其路径中间组件是符号链接，包括悬空符号链接：不跟随链接，不处理、保留并报告。
3. 确认路径不涉及上述符号链接后，`from` 路径不存在：该项无对象，跳过并在报告里注明（跨版本链式改名的中间名在上述文件状态下不存在时同样按本项跳过，先前条目对链首文件的处置不受影响）。
4. `from` 是目录或其他非普通文件，或者无法可靠确认其路径状态或读取其内容：不处理、保留并报告。
5. `from` 是可读取的普通文件：适用与上一发布版原文逐字节比对的删除守卫；一致者列为待删除项，不一致或取不到原文者保留并报告。

判定方式写死：先完成全部映射校验，再对全部 `from` 完成上述逐项状态与删除守卫判定，最后统一删除判定合格者，不许边删边判。实际删除时，若发现候选文件已不再满足判定时的路径状态或内容条件，须跳过该项、保留并报告；删除失败也须报告，不影响更新完成。
