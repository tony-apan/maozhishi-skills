# 站点 AI 配置与语言策略

## 一、这份文件管什么

两件事：① 站点的 AI 能力靠用户自己的大模型 API Key 驱动，用户问到、或施工中需要 AI 写产品、写文章、做翻译时，照第二节引导他把 Key 绑到站点后台；② 网站要不要开多语言、怎么做多语言市场，照第三节的定版策略给建议。官方原文见教程索引里的《绑定 AI API》与《开启网站多语言》两篇。分工：产品事实（字段、参数、平台行为）以官方文档为准，本文件管策略立场与引导口径，两者冲突时先按这个分工对齐，不要拿本文件硬顶官方事实。

## 二、绑 AI API：引导流程

### 为什么要绑

站点本身不带 AI。绑上用户自己的大模型 API Key 后，后台才能用 AI 写产品、写文章、做翻译、做多语言。费用由模型服务商按 Token 用量收，不经建站平台；日常写文案和翻译的用量通常花费不高，具体以服务商实时价格为准。

### 分工：用户只做三件，其余你代办

- **用户亲手做**：去模型服务商官网注册账号（页面提示实名就照做）、小额充值、创建 API Key 并当场存好（交给 AI 时走安全录入卡，见下）——就这三件，必须他本人来。
- **Key 的交接**：让用户通过安全凭据录入卡把 Key 存进保险库，你用保险库里的 Key 去后台填写，全程不读明文；**不要让用户把 Key 发到聊天里**，也不要把 Key 写进任何工作文件、截图或记录。截图、录屏里出现 Key 时先提醒打码。
- **你代办**：进站点后台「设置 → AI API 配置」，选服务商、填四项、点测试连接、成功后保存，并把连接状态读回给用户看。

### 四步流程

1. **选模型**：默认 DeepSeek，价格低、配置简单；有长文档、PDF、表格要处理时可选 Kimi；其余按下方选型表。
2. **建 Key**：引导用户在服务商开放平台充值（DeepSeek 官方示例为 ¥10、¥20 或 ¥100，支持支付宝、微信）后创建 API Key。**Key 只显示一次**（官方文档对 DeepSeek、Kimi 均如此标注，其他服务商以其规则为准），创建后立刻存进他自己的密码管理工具；要交给你去后台填写时，只走上面说的安全录入卡进保险库这一条路。丢了只能重新创建一把。
3. **后台填四项**：先在配置页选好服务商，再填四项——Base URL（按服务商文档填，DeepSeek 是 `https://api.deepseek.com/v1`）、API 格式（DeepSeek 选 OpenAI 兼容）、API Key（保险库里的那把）、模型 ID（填真实 ID，DeepSeek 日常与翻译用 `deepseek-chat`）。
4. **测试并保存**：先点「测试连接」，显示连接成功再点「保存」；失败先查四项有没有填错、Key 有没有多复制空格，再查服务商账号余额。

### 选型速查

- **DeepSeek**：便宜，日常写文案、翻译、整理产品资料；`deepseek-chat` 为日常档。**新手默认从它开始。**
- **Kimi**：中文资料和长文档处理强，适合读 PDF、表格；需要看截图、页面图片时选带视觉的型号。
- **GLM**：速度快，适合批量处理。
- **OpenAI / Claude / Gemini**：英文内容、复杂任务、长内容与多语言任务更强，按用户已有账号和预算选。
- **注意**：ChatGPT Plus 这类订阅会员不是 API，绑不了；要用 OpenAI 必须去其开放平台单独建 API Key。
- 日常翻译和写文案不要选推理档、Pro 档：更贵更慢，效果不体现在这类活上。

### 换绑与排障

- 换模型或服务商：在同一配置页重选服务商、改四项、重新测试保存即可，不用删旧配置；已生成的内容不受影响，只影响之后的新生成。
- 测试失败排查顺序：Key 是否完整无空格 → Base URL 与模型 ID 是否真实无误 → 账号余额是否充足 → 服务商官网能否打开（打不开多半是服务商侧问题，稍后再试）。
- 生成质量变差：多半是换了不合适的模型，换回原模型或换更强的模型，不要在内容上瞎补。

## 三、语言策略（定版）：不开主站多语言，走站群

### 结论先行

用户问多语言、翻译整站、要做小语种市场时，给这套建议：**不建议在主站开启平台的多语言功能；先把英语站做完整、跑出效果；之后要打某个地区或小语种市场，单独为它建一个当地语言的独立站，针对当地市场单独做内容和优化。多个独立站组成站群，效果比一个站开多语言更好。**

### 推荐路线

1. **先英语**：主站默认语言用英语（目标市场以英语国家为主时），产品、文章、页面、菜单、联系信息全部做完整，先跑出收录和询盘。
2. **见效后逐个扩站**：哪个地区有反馈、有市场，就为它新建一个独立站——当地语言、当地客户搜的词、当地市场在意的内容，逐站单独优化、单独验收。
3. **站群运营**：每个站都是完整独立站，各自绑域名、各自维护更新；新站可以复用主站的产品事实底稿，但文案按当地市场重写，不整站搬运机翻。

### 为什么站群更好（跟用户讲的口径）

- 平台多语言是把一份内容整站机翻成多个语言版本：参数、品牌名、本地说法容易失真，翻完还要逐语言人工核对，原文每改一次、各语言版本都要跟着重检。
- 独立站每种语言都是一份为当地市场单独做的内容：客户搜什么词、关心什么参数、习惯什么说法，都能针对性地写，更容易把当地市场的收录和信任做扎实。
- 主站只用一种语言，语言信号干净，不被多语言版本互相稀释。
- 一个市场一个站，哪个站要调整、暂停、换方向，都不牵连其他站。

### 立场强度：建议，不是拦截

先把上面的理由讲清、给出推荐；**用户听完仍要开多语言的，照第四节的官方流程完整引导他开**，不拒绝、不拖延，也不要反复劝。用户坚持开、但第四节的前置（内容未完整或 API 未绑）不满足时，先帮他补齐前置再开，并讲清为什么要先补——这是流程顺序，不是把建议变回拦截。开完之后把逐语言验收（尤其参数、品牌名、联系方式人工确认）盯到底。

## 四、用户坚持开多语言时：官方流程

1. **前置两件**：默认语言的内容基本完整（产品、文章、页面、菜单、联系信息都已确认）；AI API 已绑定并测试连接成功——没绑 API，系统无法翻译。
2. **添加语言**：后台「设置 → 站点语言」→「添加语言」，只勾真实目标市场的语言，不为好看全开。**默认语言非必要不换**：更换会改变已收录页面的语言信号，影响搜索收录的持续判断。
3. **等翻译完成**：添加后系统在后台整站翻译，前台照常访问。回「站点语言」看每种语言的**已翻译／未翻译／翻译失败**三个数，后两个不为 0 就还没翻完，不要把翻译中的版本当最终结果推广。
4. **补翻**：多种语言都不全，点「全站翻译」；只有一种不全，点该语言行末菜单里的「重新翻译」。任务进行中不要反复点击。
5. **前台验收**：前台有语言切换入口（官方文档标注在右上角，实际位置以当前主题为准），逐个语言切过去查菜单、页面、产品、文章。注意：网站会按访客的浏览器语言自动匹配已启用语言，没启用就回退默认语言——自己用中文浏览器打开显示中文，不是翻译失败。最后逐语言人工确认产品参数、品牌名、联系方式，AI 翻译只是初稿。
