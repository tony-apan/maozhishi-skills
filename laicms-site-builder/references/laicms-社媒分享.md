# 社媒分享包（文章发布后的固定成品）

这份文件定社媒分享包的规格：每篇文章发布后，照这里生成一份现成文案，用户（或他的 AI）复制就能往各平台发。分发的归属、移交与防重复记录按 SKILL 第八节「发布后社媒分发」执行，本文件只管分享包本身怎么生成、文案怎么写。

## 一、什么时候生成、生成什么

- **时机**：每篇文章（含每日更新的文章）发布并验收通过后，当场生成一份，不攒批、不隔天补。
- **内容**：一篇文章一份分享包，含四个平台的现成文案——Facebook、X、领英（LinkedIn）、WhatsApp（发状态或转发到频道/群的文案）。用户没在用的平台不硬凑，只出他在用的那几份。
- **语言**：随站点语言。英文站全英文，中文站全中文，不混搭。
- **存放**：跟文章的 Markdown 原稿一起存进文章存档地，文件名与文章对得上；发没发、发到哪、结果链接回填全仓共用的发布记录（见 SKILL 第八节），不在这里另起一套记录。

## 二、每份文案的构成

四个平台共用一个骨架，每份文案逐项齐：

1. **第一行是钩子**（打法见第三节），不许用「新文章发布了」「分享一篇博客」这类话开头。
2. **一句价值点**：这篇能帮买家办成什么事、避开什么坑。只用文章里已确认的事实，不另编卖点、参数和承诺。
3. **文章链接**：完整链接，单独一行，不缩在句子中间。
4. **话题标签**：3–5 个行业词（口径见第三节），放在文案末尾。
5. **配图指定**：写明用哪一张图，还要带上这张图的标识——把图片文件名写出来（照媒体库里的实际文件名写），不许只写「本文封面图」这类对不上号的说法。选图顺位写死：① 文章主图（封面图）；② 没有封面图时，用文章主讲产品的产品主图；③ 再没有，用全站品牌图。文章主讲某个具体产品时，产品主图可以直接打头。顺位里一张都没有，才算缺图——当场报缺，不许静默跳过，也不许随手拿一张不相干的图顶替。

各平台在骨架上这样微调：

- **Facebook**：可以稍长，价值点可以写两句；钩子、价值点、链接、标签之间空行分段，看着透气。
- **X**：压进一条推文的长度，字数口径写死——免费账号一条上限 **280 字符**，文案里的链接不论实际多长、按 X 的口径固定计 **23 字符**。产出后逐份按这个口径实数一遍再交包；超限时先砍修饰词、再砍价值点，数字和条款不许砍，砍完重新数，还超就换个更短的钩子重写，不许带着超限的文案交包。标签减到 2–3 个。
- **领英**：口吻最专业，可以比其他平台多一句行业判断；**文案第一行单独标一行【人工发布】**——领英风控严格，只许人手动发，完整禁令见 SKILL 第八节的领英风控警告。这个标记是给执行者看的：存进分享包（存档）的文案里**不许删**，要一直留着；用户本人手动发布时，可以删掉这一行再发、只发正文。
- **WhatsApp**：最短，口语化的转发风：一句钩子加链接就够，标签可以省；适合发状态，或转发到频道、客户群。

## 三、钩子打法（重点，逐条执行）

文案是写给目标采购商看的——零售买家、批发商、采购负责人，不是写给同行看的，也不是写给粉丝看的。

- **不许自嗨**：「我刚发了一篇新文章」「我们的博客更新了」这类开头一律禁用。买家不关心你发没发文章，只关心他自己的问题解没解。
- **每篇至少选一个主钩子角度**（拿不准时，三种各写一版，放进分享包让用户挑）：
1. **痛点式**：点出买家正在头疼的具体问题——交期不稳、起订量太高、品控翻车、询盘发出去没人回、退货率高。把他的难处说出来，他才会停下来看。
2. **数字式**：把文章里的具体参数或条款数字提到第一行——起订量、交期天数、规格数值、检查项的条数。数字必须与文章正文和产品事实底稿一致，不许为了抓眼球改数、凑数。
3. **提问式**：用买家会搜、会问的问题开头——就是他会在搜索引擎里打、或者向同行打听的那句话。
- **一条钩子只打一个点**，不要在一行里塞两三个问题。
- **语气专业可信**：像行业里的行家在提醒，不像销售在吆喝。促销腔的词禁用（「火爆」「限时抢」「全网最低」这类）；感叹号不堆砌，全篇最多一个，通常一个都不用。
- **标签 3–5 个**：用买家和行业里真在用的词，按站点品类选（如批发、采购、品类词）；不堆量，不蹭与文章无关的热词。

## 五、频率与红线

- **不刷屏**：同一篇文章在同一个平台只发一次（口径与 SKILL 第八节的发布记录、状态机一致）；新文章之间留正常间隔，不在短时间内连珠炮发帖。
- **已发布是终态，不许重发**：一篇文章在某个平台一旦发布成功（状态＝已发布），同一篇文章不得再发到同一平台——没有「隔段时间换个钩子再发一遍」的二次传播口子。发错了（发错账号、文案或链接有误）也不许靠重发纠正：先按 SKILL 第八节状态机核实平台上的实际状态，再由指定执行者在共用发布记录里处理收尾，两处口径以 SKILL 第八节为准。
- **领英红线**：领英只许人工发布，自动发布、自动加人、自动私信、自动点赞评论一律不许；分享包里领英文案首行的【人工发布】标记，在存档的分享包里不许删，用户本人手动发布时可以删掉这一行再发（与第二节口径一致）。完整口径见 SKILL 第八节「发布后社媒分发」的领英风控警告，两处互相指向、以 SKILL 为准。
- **事实红线**：文案里的每个数字、每条承诺都要能回指到文章正文或产品事实底稿；对不上就先改文案，不许将就发。
