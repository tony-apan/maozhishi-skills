# 用户本地工作区模板（workspace-template）

这是给每位使用者建「本地真源」的起点：把整个目录复制到你自己的电脑/工作区，改名为你的工作区即可。所有模块（建站、获客、B2B、社媒、广告）都只往这里读写资料，不散落在聊天记录里。

## 结构：根共用区＋分区分层

一个工作区装全部模块，内部先分区：根目录只留整仓共用的东西，每个模块有自己的分区，分区内沿用 30/40/50/90 的分层习惯（任务、产出、数据、交接）。分区列序固定：`memory/` 第一、`laifaxin/` 第二、`allincms/` 第三，其余模块分区按登记先后排、`misc/` 垫底。

| 位置 | 放什么 |
| --- | --- |
| `00-inbox/` 收件 | 用户给的一切原始资料先进这里（整仓共用），未整理不引用 |
| `10-sources/` 来源登记 | 每份资料登记来源、日期、可信度（整仓共用） |
| `20-knowledge/` 知识底稿 | **共用事实源**：公司档案、产品事实底稿、素材索引——各模块取数只认这里确认过的事实 |
| `90-handover/` 交接 | 整仓交接：进度、卡点、待办；中断后照它续接 |
| `memory/` 记忆 | 用户档案、已定口径与重要决定、分主题业务记忆、未完成事项 |
| `laifaxin/` 来发信 | 分区内 30 任务（计划排期）、40 产出（日报、开发信稿）、50 数据（台账、找客记录、开发状态）、90 交接 |
| `allincms/` 建站 | 分区内 30 任务、40 产出（文章原稿主本）、50 数据（发布记录、站点设置）、90 交接 |
| `misc/` 杂项 | 归不进已知分区的零散文件；`misc/pending/` 是待问区，只存本地、不进备份 |

根目录下原有的 `30-tasks/`、`40-output/`、`50-data/` 三层保留给整仓级与未分模块的过渡使用，新资料优先落对应分区。每个目录有一个 `INDEX.md` 写清放什么、入口文件是哪个；根目录 `INDEX.md` 是总索引，备份地记录也记在那里，找东西先看索引。

## 资料库四格与七层的对应

- 公司档案 → `20-knowledge/company-profile.md`（模板已备）
- 产品事实底稿 → `20-knowledge/产品事实底稿-<产品名>.md`（一产品一档，模板已备）
- 素材库 → 原文件放 `00-inbox/` 或云盘，索引记在 `20-knowledge/asset-index.md`
- 数据与台账 → 对应分区的 `50-data/`（台账在 `laifaxin/50-data/`）
- 长期记忆 → `memory/`

## 同步与安全

- 整个工作区按《备份与换账号接续规格》同步进你本人专属的备份地：固定名 `maozhishi-backup` 的 GitHub 私有仓或 Google 云盘文件夹，一处为主、可选双备份（换设备、换 Muse 账号靠它衔接）。
- 密码、令牌永不进本工作区、不进任何备份；凭据只走 Muse 密码库。台账含联系人明细，只进你本人私有的备份地、且要经你明确同意；聊天与邮件原文不进备份。
- 新资料先入格、再被引用；库里没有的信息，Muse 必须显名说缺，不许猜、不许编。
